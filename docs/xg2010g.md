# Gemtek XG2010G profile

This fork adds an explicit **Gemtek XG2010G** build profile for the Airoha
AN7581 NPU firmware.

## Build

```sh
make xg2010g-nowifi
```

Equivalent explicit form:

```sh
make SOC=AN7581 WIFI=NOWIFI BOARD=XG2010G
```

Output:

```
build/AN7581_XG2010G_NOWIFI/
  firmware.elf
  firmware.map
  npu_rv32.bin
  npu_data.bin
```

The boot version string includes `XG2010G`, which makes it easy to
distinguish this test image from generic `AN7581 + NOWIFI` builds.

## Stage 1 scope

The first profile is intentionally conservative.

It does:

- select all eight AN7581 NPU harts;
- disable WiFi-specific datapaths with `NOWIFI`;
- keep the existing AN7581 PPE/HWNAT initialization;
- keep AN7581 NPU bridge/tunnel support;
- expose `HAS_XG2010G` as a compile-time extension point;
- reject accidental XG2010G builds on any SoC/WiFi combination other
  than `AN7581 + NOWIFI`.

It deliberately does **not** yet:

- copy the AN7583 GPON DBA worker to AN7581;
- change PPE bind/ageing thresholds;
- change PPE/QDMA WAN mappings;
- change xPON registers;
- repartition NPU bridge channels among extra harts;
- force Linux flows into hardware.

Those changes require measurements from the real XG2010G first.

## Expected hart map in the initial profile

With `AN7581 + NOWIFI`, all eight harts boot and run the common NPU
initialization/self-test. After dispatch:

| Hart | Initial XG2010G profile role |
|---:|---|
| 0 | NPU init, mailbox, PPE/HWNAT control |
| 1 | debug/command idle loop |
| 2 | timer interrupt + debug/command idle loop |
| 3 | package/capability check + debug/command idle loop |
| 4 | debug/command idle loop |
| 5 | debug/command idle loop |
| 6 | debug/command idle loop |
| 7 | AN7581 tunnel/NPU-bridge loop |

An idle hart is not powered off. It remains alive in the firmware debug
loop and can later be assigned XG2010G-specific work.

## XG2010G optimization plan

The board profile gives later experiments a clean compile-time boundary.
The next useful changes should be introduced one at a time and compared
against stock Airoha firmware and the unmodified ClankerNPU profile.

### 1. PPE/QDMA observability

First expose the board-relevant values already used by the HWNAT setup:

- `hwnat_wan_mode`
- `hwnat_wan_xsi`
- `hwnat_ae_wan_sel`
- `hwnat_xpon_hal_api_ng`
- PPE/QDMA port-selection registers
- PPE BND/UNB/ageing state
- NPU bridge queue/credit state

This tells us how Ethernet WAN and the XG2010G PON path are actually
mapped before changing any register values.

### 2. Flow statistics

`HWNAT FLOW_STATS_SETUP` is currently not implemented in ClankerNPU.
Implementing and validating it is a high-value XG2010G task because it
can provide real per-flow/per-path hardware counters to the LuCI
NPU/PPE monitor.

### 3. PPE profile tuning

Only after baseline data is collected, test changes to:

- bind threshold;
- unbound ageing;
- bound TCP/UDP ageing;
- keepalive;
- parser/ethertype coverage;
- flow-table occupancy/collision behaviour.

The goal is higher hardware-offload coverage, not simply larger values.

### 4. Extra hart work

Do not split ordinary routed packets across RISC-V harts if PPE can
forward them directly. The spare harts are more useful for independent
NPU-bridge channels, telemetry, or other firmware work that does not
turn the NPU into a software forwarding engine.

A later experimental map may use spare harts for channel-specific work,
but it must account for AN7581 hardware mutex ownership aliasing between
harts 0..3 and 4..7.

### 5. PON and IPTV

XG2010G PON/EN7572 support must be derived from the actual XG2010G host
driver and hardware interface. Do not enable the AN7583 FTTR/GPON DBA
path by assumption.

Likewise, IPTV multicast hardware replication primarily belongs in the
Linux/Airoha PPE multicast path. The NPU firmware can add telemetry or
special-channel handling, but should not copy every multicast packet in
software when PPE can replicate it.

## Validation

For the first image, verify only that the new profile behaves like the
generic AN7581+NOWIFI firmware while being clearly identifiable:

1. all eight harts pass self-test;
2. the version string includes `NOWIFI.XG2010G`;
3. no NPU traps are recorded;
4. HWNAT/PPE initialization succeeds;
5. eligible traffic still creates PPE hardware flows;
6. Ethernet and PON behaviour is unchanged from the baseline.

Only after this stage passes should XG2010G-specific datapath tuning be
enabled.
